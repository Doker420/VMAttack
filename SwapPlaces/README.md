# Поменяйся местами

Отдельная standalone Roblox-игра о взаимном обмене управляемыми персонажами и внутриигровыми скинами. Проект не зависит от AeroRush или BlockSiege.

## Что реализовано

- **Обмен телами:** после согласия второго игрока и подтверждения покупки сервер меняет `Player.Character` у двух участников. Каждый управляет исходной моделью персонажа партнёра; клиент перепривязывает камеру к новому Humanoid.
- **Возврат:** кнопка возврата, смерть одного из тел, выход участника или таймер завершают сессию и загружают обоим их собственные аватары.
- **Оплата любым участником:** после согласия либо инициатор, либо принявший игрок может оплатить Developer Product. Состояние offer, payer, Product ID и receipt проверяются сервером.
- **Взаимный обмен скинами:** каждый выбирает один собственный торгуемый скин. Изменение выбора сбрасывает подтверждения обеих сторон; commit выполняется только после двух подтверждений и повторной проверки владения.
- **Без копий в игровой экономике:** выбранный скин уходит из инвентаря одного игрока и появляется у другого, а встречный скин переходит обратно. `Default` не торгуется.
- **Стартовая коллекция:** `Default` плюс один из семи торгуемых скинов. Все семь входят в starter pool, поэтому каждый может попасть в экономику без магазина или подарка.
- **Социальная площадь:** procedural plaza, две swap-площадки, trade booth, галерея восьми скинов, prompts и защитные стены.
- **UI:** список игроков, страницы ТЕЛО / СКИНЫ / ГАРДЕРОБ, consent/payment/revert состояния, горячие клавиши `B`, `T`, `I`, compact layout для узких и низких окон.

> Скины являются собственными внутриигровыми записями и procedural-аксессуарами. Это **не** Roblox Limiteds и не передача официальных Roblox avatar items.

## Запуск

### Готовый place

1. Откройте `SwapPlaces/SwapPlaces.rbxlx` в Roblox Studio.
2. Опубликуйте place в **своём** Roblox experience.
3. Для сохранений включите Studio API access только в своём тестовом experience. В Studio по умолчанию используется memory-профиль (`PersistInStudio = false`).
4. Для локальной проверки используйте как минимум двух тестовых клиентов: **Test → Clients and Servers → 2 Players**.

### Rojo source

Конфигурация находится в `default.project.json`. Source разделён на:

- `ReplicatedStorage/SwapPlaces`: Config и SkinCatalog;
- `ServerScriptService/SwapPlacesServer`: Main и пять server services;
- `StarterPlayer/StarterPlayerScripts`: клиентский LocalScript.

Rojo не входит в архив; его можно установить отдельно и использовать штатный `rojo serve` / `rojo build` workflow.

## Настройка Robux

По умолчанию:

```lua
SwapProductId = 0
SwapRobuxPrice = 25
EnableStudioTestPurchases = true
```

**Live Robux-покупки отключены, пока `SwapProductId = 0`.** Нулевой ID не открывает live purchase и не выдаёт бесплатный live-обмен.

Для live-настройки владельцу experience необходимо:

1. Создать Developer Product именно для смены персонажей.
2. Установить продукту цену 25 Robux либо согласовать цену продукта и `Config.SwapRobuxPrice`.
3. Вставить настоящий ID в `SwapProductId`.
4. Проверить `ProcessReceipt` на настоящем продукте в контролируемом live-тесте.

В Studio кнопка выполняет явно подписанный **TEST-ОБМЕН · БЕЗ ROBUX**, если включён `EnableStudioTestPurchases`. Это не проверка настоящего платежа. В live единственный путь выполнения платного обмена — серверный `MarketplaceService.ProcessReceipt` с совпавшими Product ID, payer и активным offer.

## Правила взаимодействия

### Тела

1. Нажмите **ТЕЛО** возле другого игрока.
2. Адресат должен нажать **СОГЛАСИТЬСЯ**. Инициатор не может принять собственный offer за другого.
3. После согласия любой участник нажимает оплату; платит только нажавший.
4. После серверного подтверждения игроки получают персонажей друг друга на 180 секунд.
5. **ВЕРНУТЬСЯ В СВОЁ ТЕЛО** завершает обмен для обоих.

Offer можно отклонить или отменить до платежа. Отмена purchase prompt возвращает состояние `Accepted`, а не оставляет постоянный PaymentPending.

### Скины

1. Нажмите **СКИН** возле другого игрока.
2. Каждый выбирает собственный скин и подтверждает обмен.
3. После первого подтверждения второй игрок ещё может изменить выбор — тогда подтверждения сбрасываются.
4. После второго подтверждения сервер одновременно меняет владение в двух server-owned профилях.

Обмен телами и торговая сессия взаимно блокируются, чтобы исключить конфликт состояний.

## Проверки и границы

См. `TEST_REPORT.md`. Luau compile/analyze, native suites с Roblox mocks, static UI geometry и XML/ZIP parity не заменяют Roblox Studio или live acceptance.

Перед публикацией обязательно проверить:

- два реальных клиента: управление чужим телом, камеру, анимации, смерть/respawn и возврат;
- настоящий Developer Product, receipt retry/idempotency, отмену и disconnect во время покупки;
- DataStore load/save и поведение при сбое сохранения двух отдельных профилей;
- rendering, touch, сетевую задержку, physics/network ownership и производительность.

Trade commit атомарен внутри одного server process после всех проверок. Два профиля сохраняются отдельными DataStore keys; это не распределённая транзакция DataStore и не должно выдаваться за доказанную crash-recovery гарантию без отдельного live-теста.
